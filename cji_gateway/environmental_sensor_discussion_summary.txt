6.1 HOW TO VERIFY THIS VALUE DIRECTLY IN THE GATEWAY
----------------------------------------------------
While the gateway doesn't decode "Celsius" on its default web pages, you can verify
the data passing through the gateway using two direct methods:

Method 1: Check UART Hardware Byte Counters inside the Gateway Linux Kernel
Run this command in the gateway shell (via Telnet or Web Console):
  cat /proc/tty/driver/serial

Output:
  0: uart:16550A mmio:0x1E000C00 irq:34 tx:1073 rx:0
  1: uart:16550A mmio:0x1E000D00 irq:35 tx:56   rx:0
  2: uart:16550A mmio:0x1E000E00 irq:36 tx:856  rx:3368 RTS|CTS|DTR|DSR|CD|RI

Every time our computer polls the sensor:
  - UART 2 (/dev/ttyS2) 'tx' counter increments by 8 bytes (the query frame).
  - UART 2 (/dev/ttyS2) 'rx' counter increments by 49 bytes (the sensor response).
This is physical proof that electrical bytes are crossing the gateway's RS-485 pins.

Method 2: Packet Sniffing with tcpdump on the Gateway
Run this on the gateway to view the raw Modbus frames passing through in real time:
  tcpdump -i any -nn -X 'port 5021 and (tcp[tcpflags] & tcp-push != 0)'

Output shows the exact 8-byte query and 49-byte response as it passes through the OS:
  Request:  ff03 0009 0005 4015
  Response: ff03 0a19 4e0f 5e00 0000 0000 00d1 f3


6.2 WHY THE VALUE IS NOT SEEN DIRECTLY ON THE GATEWAY WEB PAGES
---------------------------------------------------------------
* The WMD-7621U is an Industrial IoT Gateway / Router, not a dedicated weather display.
* In industrial automation, the gateway's job is to act as a transparent Layer-2 /
  Layer-3 bridge connecting field buses (RS-485) to IP networks (Ethernet/4G/WiFi).
* Industrial gateways are device-agnostic: a customer might connect an electricity meter,
  a solar inverter, a water flow valve, or a weather sensor. The gateway firmware
  cannot know what brand or model of sensor is connected, so it does not have hardcoded
  screens to parse third-party proprietary register tables.
* Instead, it exposes standard industrial protocols (ser2net, mbusd Modbus TCP, MQTT)
  so SCADA systems, PLCs, cloud servers, or custom programs can query and display them.


6.3 THE COMPLETE WORKFLOW FROM START TO END
-------------------------------------------
1. Physical Generation:
   The physical environmental parameters (temperature, humidity, noise, particulates)
   are measured by the sensor probes and converted by the sensor's internal CPU
   into 16-bit integer registers.
2. Polling Request:
   Your PC connects to 192.168.11.1:5021 via TCP and sends an 8-byte Modbus RTU frame:
   [FF 03 00 01 00 16 80 1A].
3. Gateway Bridging (TCP -> UART):
   The gateway's `ser2net_s2` daemon receives the 8 bytes from the TCP socket and writes
   them to `/dev/ttyS2`.
4. Physical Wire Transmission:
   The gateway's RS-485 transceiver translates TTL logic into differential voltage
   pulses on wires A (TX+) and B (RX-) at 9600 baud (8N1).
5. Sensor Response:
   The sensor checks the CRC, processes function code 0x03, and replies over wires A & B
   with a 49-byte frame containing 44 bytes of data and a 2-byte CRC-16.
6. Gateway Bridging (UART -> TCP):
   The gateway's UART controller triggers IRQ 36; the Linux kernel buffers the bytes into
   `/dev/ttyS2`. `ser2net_s2` reads `/dev/ttyS2` and forwards the 49 bytes over TCP port 5021.
7. PC Application Decoding:
   The PC verifies the CRC-16 checksum, extracts each 2-byte register, and applies the
   mathematical conversion formulas to display Celsius, %RH, dB, and ug/m3.

7. BYTE-BY-BYTE BREAKDOWN OF TRANSMITTED & RECEIVED PACKETS
================================================================================

A. THE 8-BYTE REQUEST PACKET:
   Hex: FF 03 00 01 00 16 80 1A
   - Byte 0: 0xFF      -> Slave Address (255)
   - Byte 1: 0x03      -> Function Code (Read Holding/Input Registers)
   - Bytes 2-3: 0x0001 -> Starting Register Address (0x0001 = Noise)
   - Bytes 4-5: 0x0016 -> Number of Registers to Read (22 registers)
   - Bytes 6-7: 0x801A -> CRC-16 Checksum (Low: 0x80, High: 0x1A)

B. THE 49-BYTE RESPONSE PACKET:
   Hex: FF 03 2C 025C 0000 0000 0000 0000 0000 0004 0006 194E 0F5E 0000 ... 4A7F
   - Byte 0: 0xFF      -> Slave Address Confirmation
   - Byte 1: 0x03      -> Function Code Confirmation
   - Byte 2: 0x2C      -> Byte Count (44 data bytes = 22 registers * 2)
   - Bytes 3-4:   0x025C (604)  -> Noise: 604 / 10.0 = 60.4 dB
   - Bytes 5-14:  0x0000        -> Gas Channels (H2S, SO2, NO2, CO, O3)
   - Bytes 15-16: 0x0004 (4)    -> PM2.5: 4 ug/m3
   - Bytes 17-18: 0x0006 (6)    -> PM10:  6 ug/m3
   - Bytes 19-20: 0x194E (6478) -> Temp:  (6478 / 100.0) - 40.0 = 24.78 °C
   - Bytes 21-22: 0x0F5E (3934) -> Humid: 3934 / 100.0 = 39.34 %RH
   - Bytes 23-36: 0x0000        -> Pressure, Wind, Rain, Radiation, Lux, UV
   - Bytes 37-38: 0x0023 (35)   -> CO2:   35 ppm
   - Bytes 39-46: 0x0000        -> Reserved / Negative Ions
   - Bytes 47-48: 0x4A7F        -> CRC-16 Checksum (Low: 0x4A, High: 0x7F)
